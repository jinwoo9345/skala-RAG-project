## 1. [P0] Web Search가 핵심 논문의 arXiv 페이지만 찾아옴

**실제 동작 [확인]**
검색 자체는 동작한다. 하지만 웹 근거(`web-da6e58e6…` 등)가 모두 핵심 논문의 arXiv 페이지에서 나와 REFERENCE [1], [2]로 합쳐졌다. 시장·이해관계자 평가에 외부 자료가 하나도 없다.

**원인**

- `agents/common.py:150`: `f'"{primary}" {terms}'`가 논문 제목 일부를 따옴표로 감싸 정확한 구절 일치를 강제한다. 이 구절은 사실상 논문에만 있다.
- `agents/common.py:166`: 대체 질의는 관련 결과가 0건일 때만 실행된다(`if relevant: break`). 첫 질의가 arXiv를 찾아오므로 대체 질의는 실행되지 않는다.
- 대체 질의의 `"CXL-PIM"`은 프로젝트 내부 명칭이라 논문의 표현("CXL-PNM", "PNM-KV")과 일치하지 않는다.
- `nodes/verification.py:42`: 반대 근거 질의에 한국어 claim 문장 350자를 그대로 넣는다.

**해결 방안**

1. 질의에서 따옴표를 없앤다.
2. `TECH_PROFILES`의 CXL-PIM 별칭에 "CXL-PNM", "PNM-KV"를 질의용으로 사용한다.
3. 웹 결과에서 핵심 논문 URL(`paper_ids`의 arXiv ID가 포함된 URL)을 제외한다. 그러면 대체 질의도 정상적으로 실행된다.
4. 반대 근거 질의는 claim 문장 대신 `기술명 + 기준의 QUERY_TERMS + limitations`로 만든다.

**시장조사가 진행되지 않는 추가 원인**

위 수정만으로는 시장 자료가 들어오지 않는다. 남는 원인은 두 가지다.

- **질의 대상 [확인]:** 시장 기준 질의도 항상 개별 기술명으로 만든다. 예: `"Inference Tiered Memory Expansion" market size growth forecast`. ITME나 CXL-PIM 같은 연구 단계 기술에는 개별 시장 자료가 없다. 시장 규모·성장성 자료는 상위 시장(CXL 메모리, PIM/PNM) 단위로만 존재한다. 코드의 평가 지침(`EVALUATION_GUIDANCE["market"]`)은 상위 시장 자료를 쓰라고 하지만, 정작 그런 질의를 만들지 않는다.
- **출처 등급 [확인: 코드 / 영향은 추정]:** 시장 평가의 Fact는 출처 등급 4 이하만 허용한다(`FACT_MAX_TIER = 4`, `evidence.py:extract_evidence`의 `low_source_tier`). 그런데 등급 4 도메인은 `sec.gov`, `gartner.com`, `idc.com`뿐이다. TrendForce, Yole 같은 반도체 시장조사 기관은 등급 5로 분류되어, 시장 규모 수치를 Fact로 쓸 수 없다.

**시장조사를 위한 추가 해결 방안** 5. `TECH_PROFILES`에 기술별 상위 시장 검색어를 하나씩 추가한다. 예: ITME → `"CXL memory expansion"`, CXL-PIM → `"CXL processing near memory PIM"`. 6. `agents/common.py:web_sources`에서 상위 시장 성격의 기준(시장 규모·성장성, 지원 생태계, 경쟁 진영, 투자 업계)은 기술명 대신 이 상위 시장 검색어로 질의한다. 이 자료는 기존 `relevance()`에 의해 `ecosystem` 범위로 분류된다. 보고서에서도 기존 정책대로 "상위 시장 자료"로 구분해 표시된다. 7. `config.py`의 `SOURCE_PRIORITY` 등급 4에 반도체 시장조사 기관 도메인을 몇 개 추가한다. 예: `trendforce.com`, `yolegroup.com`.

**확인 방법**

- 수정 후 실행 로그 `WEB_RESULTS`에 arXiv 외 도메인이 들어오는지 본다.
- 재생성한 `report.pdf`의 4.2 시장성 절에 상위 시장 자료(CXL 메모리·PIM 시장 규모, 지원 기업)가 근거와 함께 나오는지 본다.

## 2. [P0] 반대 근거가 잘못 해석되어 요약까지 오염됨

**실제 동작 [확인]**
SUMMARY, 4.3, 5.2, 5.3, 6.3에 "ITME는 복잡한 소프트웨어 최적화 부담과 비용 문제를 가진다"는 내용이 반복된다. ITME 논문 1쪽 원문에서 이 부담은 **ITME가 비판하는 기존 방식(DPU/JBOF)의 문제**다. 반대 근거로 채택된 2건도 모두 ITME 논문 자체에서 나왔다.

**원인**

- 1번 때문에 반대 근거 후보가 ITME 논문 자체로 한정된다.
- `evidence.py:quote_exists`는 인용문이 원문에 있는지만 확인한다. 그 문장이 누구에 대한 진술인지는 보지 않는다.

**해결 방안**

- 1번의 "핵심 논문 URL 제외"를 반대 근거 후보에도 적용한다. 자기 논문이 후보에서 빠지면 이 오류는 생기지 않는다.

## 3. [P0] REFERENCE에 내부 해시 ID가 출력됨

**실제 동작 [확인]**
참고문헌마다 `• 근거 ID: CXL-PIM-p11-c5-bb678515-c9b5ce388a, web-…, counter-…` 줄이 출력된다. 이 값은 내부 추적용 해시 ID라서 독자에게는 의미가 없다. 본문 인용은 이미 `[2, p.8]`처럼 번호와 페이지로 표시된다.

**원인**

- `agents/report.py:462`: `lines.append("   - 근거 ID: " + ", ".join(ref["evidence_ids"]))`
- `tools/pdf_writer.py:139-140`: `"근거 ID:"`로 시작하는 줄을 따로 처리해 PDF에 넣는다.

**해결 방안**

- `report.py:462` 줄과 `pdf_writer.py`의 `"근거 ID:"` 분기를 없앤다. 근거 ID는 `references` State에 이미 남아 있으므로 추적에는 문제가 없다.
- 웹 출처가 별도 참고문헌으로 보이지 않는 문제는 1번을 고치면 해결된다. 지금은 웹 결과가 논문 자신이라 합쳐지는 것뿐이다.

## 4. [P1] RAG 근거가 검증 단계에서 탈락하고 수치가 사라짐

**실제 동작 [확인]**

- 재검색 2회 후에도 CXL-PIM의 "데이터 이동 방식, 실험 환경, 비교 Baseline"과 ITME의 "주요 성능 결과, 한계점"이 미확보로 남았다.
- 그러나 CXL-PIM 논문 8쪽 Methodology에 *"up to eight A100-80GB GPUs … Llama3.1-8B/70B/405B … 128K–1M tokens"*가 명시되어 있다.
- 보고서 전체에 성능 수치가 하나도 없다.

**원인 [추정]**

- 검색은 정상일 가능성이 높다. retrieval 평가셋의 `cxl-setup` 정답 페이지가 8쪽이고, README는 Hit Rate 1.000을 주장한다.
- `evidence.py:numeric_supported`는 claim의 모든 숫자가 인용문에 있어야 통과시킨다. 원문 "eight"를 claim에서 "8개"로 쓰면 탈락한다. 수치 주장에는 실험 조건 인용까지 요구된다. 그래서 수치가 들어간 근거가 대부분 탈락했을 가능성이 높다.

**해결 방안**

1. 먼저 실행 로그 `EVIDENCE_EXTRACTED | … | reasons=`로 탈락 사유를 확인한다.
2. `numeric_mismatch`나 `numeric_condition_missing`이 대부분이면 그 검사만 완화한다. 예를 들어 영어 수사(one~twelve)를 숫자로 바꿔 비교한다.

## 5. [P1] 보조 논문 5편이 보고서에 쓰이지 않음

**실제 동작 [확인]**
REFERENCE에 보조 논문(InfiniGen, PagedAttention, Mooncake, CENT, CacheGen)이 한 건도 없다.

**원인 [확인]**

- 보조 논문은 `agents/domain.py`에서만 검색되지만, `common.evaluate`가 finding의 기술을 ITME와 CXL-PIM으로 제한해서 실제로 채택되지 않는다.

**해결 방안**

- README의 "핵심 및 보조 논문 7편을 활용한다"는 설명을 실제 동작에 맞게 고친다. 보조 논문을 꼭 써야 한다는 요구사항이 정해지면 그때 기능을 추가한다.

## 6. [P2] TRL 판정이 보고서 안에서 모순됨

**실제 동작 [확인]**
ITME의 "실환경 검증"은 TRL 6, CXL-PIM은 TRL 5로 판정되었다. 그런데 같은 절에서 두 기술 모두 "연구용 실험 환경에 한정", "실제 운영환경 검증 없음"이라고 쓴다.

**원인**
`agents/common.py:evaluate` 프롬프트에 "연구용 테스트베드는 실환경 검증이 아니다"라는 기준이 없다.

**해결 방안**

- 평가 프롬프트의 TRL 설명에 "연구용 테스트베드·시뮬레이션은 실환경 검증으로 보지 않는다"는 한 문장을 추가한다.

## 8. [P2] `relevance()`의 약어 비교가 부분 문자열로 이루어짐

**실제 동작 [확인]**
`tools/web_search.py:relevance`는 `name.lower() in text.lower()`로 비교한다. 그래서 `"itme"`가 "comm**itme**nt"에도 일치한다.

**해결 방안**

- 약어 비교를 단어 경계 정규식(`\bITME\b`)으로 바꾼다.

### 검증 중 추가로 수정한 내용

- 웹 본문의 마크다운 기호(`**`, `#`)를 제거하고, `...`로 이은 인용문은 각 구간이 원문에 순서대로 있으면 인정한다 (`tools/web_search.py`, `evidence.py`).
- LLM이 인용문에 다른 자료의 ID를 붙이면, 인용문이 실제로 있는 유일한 자료로 바로잡는다 (`evidence.py`).
- 등급 5 웹 자료의 Fact는 버리지 않고 Opinion으로 낮춘다. `config.py` 주석의 설계 의도대로다 (`evidence.py`).
- 제품화·도입 기준은 상위 시장 자료로 어떤 주장도 만들지 않는다 (`agents/common.py`).
- 추출 프롬프트에 "대상 기술을 언급하지 않는 자료는 대상 기술을 주어로 쓰지 말 것", "수치는 원문 표기 그대로"를 추가했다.
- 보고서 출처 등급 기본값을 RAG 근거는 1로 바꾸고, 본문에 섞인 내부 근거 ID를 제거한다 (`agents/report.py`).
- 시장조사 기관 도메인(mordorintelligence, fortunebusinessinsights, marketsandmarkets, grandviewresearch)을 등급 4에 추가했다.

### 2차 추가 수정 (남은 문제 1·2와 참고문헌 표기)

- **관련 기술 오인:** `tools/web_search.py:relevance()`가 고유 명칭을 제목과 본문 앞 2,000자(`DIRECT_SCOPE_CHARS`)에서만 찾는다.
  - 근거: CMM-Ax 페이지(7,204자)에서 CXL-PIM 논문 제목은 6,280번째 글자, 하단 관련 논문 링크 목록에만 나왔다. CXL-PIM을 실제로 다루는 페이지(scilit)에서는 0번째 글자(제목)에 나왔다.
  - 결과: CMM-Ax는 `ecosystem`으로 분류되어 TRL 직접 근거에서 빠졌다.
- **보고서 서술의 오귀속:** `tools/report_writer.py` 프롬프트에 규칙을 추가했다. `scope`/`evidence_scope`가 `ecosystem`인 내용은 대상 기술을 주어로 쓰지 말고, 시장·표준·기업을 주어로 쓰며 상위 시장 맥락임을 밝힌다.
- **참고문헌 표기:** `agents/report.py:_reference_text`가 "저자·기관 정보 미확인 (발행일 미확인)" 같은 문구를 쓰지 않는다. 확인된 항목만 표시하고, 웹 자료에는 `(접근일: YYYY-MM-DD)`를 붙인다.

### 남은 문제

1. **4.2절 도입문의 주어 오귀속:** 프롬프트로 통제되지 않는 경우가 남는다. 확실히 막으려면 4.2·4.3절 도입문을 LLM 서술 대신 findings 기반으로 코드에서 만드는 방법이 있다.
2. **시장 규모 수치 누락:** 최종 실행에서도 시장 규모 금액(예: USD 1.27 billion)이 보고서에 나오지 않는다. 시장 추출의 `numeric_mismatch`가 원인으로 보이며, 정확한 불일치 형태는 추출 결과를 디버깅해야 확인된다.
3. **반대 근거 0건:** 모든 실행에서 채택된 반대 근거가 0건이다. 자기 논문 제외 후 실제 반박 자료가 검색되지 않는 것인지, 검증에서 탈락하는 것인지는 아직 확인하지 않았다.
4. **실행 간 변동:** TRL·시장 근거 수가 실행마다 달라진다(예: CXL-PIM TRL이 실행에 따라 3~4). LLM 판단에 따른 변동이다.
